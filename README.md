# Модель размещения быстрых ЭЗС — прототип

Статический сайт (GitHub Pages), все формулы считаются в браузере на JS,
данные лежат рядом в JSON. Спецификация: [docs/spec.txt](docs/spec.txt)
(текстовая выгрузка из docx), решения и находки — [docs/journal.md](docs/journal.md).

## Структура

```
index.html          точка входа статического сайта, карта, ползунок времени, паспорт
css/style.css
js/
  app.js             оркестрация: загрузка данных, состояние, обработчики, кэш опорных равновесий
  mapview.js         слои Яндекс.Карт (станции, тепловая карта спроса, центры, кандидат, соседи)
  passport.js        рендер паспорта площадки (12.2): быстрая часть (М1-М4) + медленная (М5-М7)
  demand.js          модуль 1 — спрос
  choice.js          модуль 2 — выбор станции, Хафф
  queue.js           модуль 3 — очередь и загрузка (M/M/c/K)
  equilibrium.js     модуль 4 — равновесие сети + локальный пересчёт (12.3)
  grid.js            модуль 5 — подключение к сети (R'_q, класс, субсидия)
  equipment.js       модуль 6 — перебор конфигураций, выбор ω* (8.2)
  economics.js       модуль 7 — CAPEX, NPV, окупаемость, S*/U*
  tests.js           Т1-Т8 в браузере (кнопка «Проверить модель», раздел 13)
  portfolio.js       модуль 8 — базовая линия и портфель (после 24.09)
data/
  cells.json                 сетка спроса 1x1 км (синтетика, генератор ниже)
  stations.json               действующие + плановые станции (синтетика)
  centers.json                питающие центры (синтетика)
  params.json                  все параметры модели (раздел 11 + каталог 8.1); не синтетика — перенесено из спецификации, D0 откалиброван
  reference-equilibria.json    опорные равновесия сети без кандидата (сценарий base, 2026/2030 x зима/лето x будни/выходной) — посчитаны офлайн, во фронтенд пока не подключены (браузер считает и кэширует их сам)

  generate-synthetic-data.js       генератор cells/stations/centers.json
  calibrate-d0.js                  бисекция D0 по S_obs (раздел 3.5)
  compute-reference-equilibria.js  опорные равновесия → data/reference-equilibria.json
  check-breakeven-dc60-1.js        разовая проверка формулы 9.5 (см. journal.md)
tests/
  t1-demand-conservation.js    Т1: сохранение спроса
  t2-huff-probabilities.js     Т2: вероятности Хаффа суммируются в 1
  t3-queue-vs-erlangc.js       Т3: цепь M/M/c/K против Erlang-C
  t4-balance-new-station.js    Т4: баланс при добавлении станции
  t5-hand-calc.js              Т5: сверка с независимым расчётом, fixture hand5.json
  t6-not-a-scoring-model.js    Т6: "не скоринг ли это", 50 кандидатов, тау Кендалла
  t7-breakeven-formula.js      Т7: формула S*/U* против помесячного расчёта
  t8-local-vs-full.js          Т8: локальный пересчёт против полного, 10 кандидатов
  fixtures/hand5.json          5 ячеек + 2 станции для Т5
```

## Запуск

```bash
npm run generate:data        # пересоздать синтетические cells/stations/centers.json
npm run calibrate:d0         # пересчитать D0 и записать в data/params.json
npm run reference:equilibria # пересчитать data/reference-equilibria.json
npm test                     # Т1-Т8 подряд (полные версии, включая 50 кандидатов в Т6)
npm run check:breakeven      # разовая проверка U* для DC60-1
```

Для просмотра сайта — любой статический сервер, например `npx serve .`
или `python3 -m http.server`. Открыть `index.html` напрямую (`file://`)
не получится — ES-модули и `fetch()` данных требуют HTTP.

**Нужен API-ключ Яндекс.Карт**, иначе карта не поднимется (через 8с
покажет понятную ошибку вместо вечной загрузки). Получить бесплатно на
developer.tech.yandex.ru (JavaScript API и HTTP Геокодер, нужен Яндекс ID)
и подставить в `index.html` вместо `YOUR_YANDEX_API_KEY`.

Известные упрощения:
- **Настоящих данных всё ещё нет.** cells/stations/centers.json — синтетика
  (генератор scripts/generate-synthetic-data.js), поэтому демо-спрос на
  карте лежит идеально квадратной сеткой 1×1 км, а не по форме города.
  Как появятся файлы от Бори/Сони в том же формате — просто заменить в
  `data/`, код модулей 1-7 менять не придётся.
- Перебор оборудования (модуль 6) считается только для сценария `base`.
- Быстрый черновик паспорта (клик по карте) всегда предполагает DC60-1;
  настоящий перебор всех конфигураций и выбор ω* считается отдельным,
  более медленным проходом (до 8 конфигураций × 8 локальных равновесий).
  На холодном кэше опорных равновесий — до ~17с (первый клик после
  загрузки страницы), на тёплом — ~3.5с (укладывается в целевые 5с из
  раздела 12.3). Фоновый прогрев кэша запускается при загрузке страницы;
  полноценный Web Worker (чтобы не блокировать основной поток) не сделан —
  и на холодном, и на тёплом кэше расчёт сейчас блокирует UI.
- Для ΔS-чувствительных расчётов (локальный пересчёт, соседи, экономика)
  используется более точный порог сходимости, чем дефолтный из раздела 6.1
  — иначе расхождение с полным пересчётом превышает 2% из Т8. Подробности
  — docs/journal.md, записи от 20.09.
- U* по закрытой формуле (9.5) систематически на ~8% выше, чем даёт честный
  помесячный расчёт с тем же S* — это не баг, а разница между "годовой
  аннуитет" (CRF) и "равномерный помесячный поток". Подробности —
  docs/journal.md, запись про Т7.
- Т6 в 2026 году формально не проходит по оси времени (тау≈0.87-0.91,
  порог 0.9) — это предсказанное самой спецификацией поведение (раздел 14:
  при загрузке ~10% ось времени почти не меняет рейтинг), не баг. Т6 в
  тестах жёстко требует прохождения только для 2030. Подробности —
  docs/journal.md, запись про Т6.
- Кнопка «Проверить модель» (js/tests.js) считает Т6/Т8 в сокращённом виде
  (10 и 3 кандидата вместо 50 и 10) — иначе кнопка висела бы больше минуты.
  Полные версии — только через `npm test` в Node.
