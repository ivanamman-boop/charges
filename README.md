# Модель размещения быстрых ЭЗС — прототип

Статический сайт (GitHub Pages), все формулы считаются в браузере на JS,
данные лежат рядом в JSON. Спецификация: [docs/spec.txt](docs/spec.txt)
(текстовая выгрузка из docx), решения и находки — [docs/journal.md](docs/journal.md).

## Структура

```
index.html          точка входа статического сайта, карта, ползунок времени, паспорт
css/style.css
js/
  app.js             оркестрация: загрузка данных, состояние, обработчики
  mapview.js         слои Leaflet (станции, спрос, центры, кандидат, соседи)
  passport.js        рендер черновика паспорта площадки (12.2)
  demand.js          модуль 1 — спрос
  choice.js          модуль 2 — выбор станции, Хафф
  queue.js           модуль 3 — очередь и загрузка (M/M/c/K)
  equilibrium.js     модуль 4 — равновесие сети + локальный пересчёт (12.3)
  grid.js            модуль 5 — подключение к сети (вт)
  equipment.js       модуль 6 — подбор оборудования (вт)
  economics.js       модуль 7 — экономика (вт)
  portfolio.js       модуль 8 — базовая линия и портфель (после 24.09)
data/
  cells.json                 сетка спроса 1x1 км (синтетика, генератор ниже)
  stations.json               действующие + плановые станции (синтетика)
  centers.json                питающие центры (синтетика)
  params.json                  все параметры модели (раздел 11 + каталог 8.1); не синтетика — перенесено из спецификации, D0 откалиброван
  reference-equilibria.json    опорные равновесия сети без кандидата (сценарий base, 2026/2030 x зима/лето x будни/выходной) — посчитаны офлайн, во фронтенд пока не подключены (браузер сейчас считает полное равновесие сам при загрузке/пересчёте, это быстро: ~0.4с в 2026, ~2.5с в 2030)
scripts/
  generate-synthetic-data.js       генератор cells/stations/centers.json
  calibrate-d0.js                  бисекция D0 по S_obs (раздел 3.5)
  compute-reference-equilibria.js  опорные равновесия → data/reference-equilibria.json
  check-breakeven-dc60-1.js        разовая проверка формулы 9.5 (см. journal.md)
tests/
  t1-demand-conservation.js   Т1: сохранение спроса
  t2-huff-probabilities.js    Т2: вероятности Хаффа суммируются в 1
  t3-queue-vs-erlangc.js      Т3: цепь M/M/c/K против Erlang-C
  t4-balance-new-station.js   Т4: баланс при добавлении станции
  t5-hand-calc.js             Т5: сверка с независимым расчётом, fixture hand5.json
  t8-local-vs-full.js         Т8: локальный пересчёт против полного, 10 кандидатов
  fixtures/hand5.json         5 ячеек + 2 станции для Т5
```

## Запуск

```bash
npm run generate:data        # пересоздать синтетические cells/stations/centers.json
npm run calibrate:d0         # пересчитать D0 и записать в data/params.json
npm run reference:equilibria # пересчитать data/reference-equilibria.json
npm test                     # Т1-Т5, Т8 подряд
npm run check:breakeven      # разовая проверка U* для DC60-1
```

Для просмотра сайта — любой статический сервер, например `npx serve .`
или `python3 -m http.server`. Открыть `index.html` напрямую (`file://`)
не получится — ES-модули и `fetch()` данных требуют HTTP.

Известные упрощения:
- Опорные равновесия в JSON посчитаны только для сценария `base` (8 из 16
  комбинаций раздела 12.3); фронтенд их пока не использует — считает сам.
- Кандидат на клике всегда DC60-1 (заглушка) — перебор конфигураций и выбор
  ω* появятся во вторник вместе с модулем 6.
- Для ΔS-чувствительных расчётов (локальный пересчёт, соседи) используется
  более точный порог сходимости, чем дефолтный из раздела 6.1 — иначе
  расхождение с полным пересчётом превышает 2% из Т8. Подробности и почему
  это не баг локального метода — docs/journal.md, запись от 20.09.
