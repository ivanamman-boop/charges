# 3. Варианты использования

Методика. Варианты использования записаны по шаблону А. Коберна. Для каждого указаны основной актор, цель, предусловия, триггер, основной поток, альтернативные потоки и постусловие. Номер альтернативы показывает шаг основного потока, на котором она ответвляется. Версия кода 0ed6276 от 28.10.2026, репозиторий github.com/ivanamman-boop/charges, сайт ivanamman-boop.github.io/charges и cm641193.tw1.ru. Документ сверен с кодом 28.10.2026.

## UC-01. Оценить площадку

| | |
|---|---|
| Основной актор | Аналитик развития сети |
| Цель | Получить паспорт точки до заявки на подключение |
| Предусловия | Сайт загружен, расчёт зон и равновесие сети без кандидата для выбранных условий готовы |
| Триггер | Выбор точки на карте зон |
| Основной поток | 1. Аналитик выбирает сценарий (30% или 80%) и год (2026, 2028, 2030). 2. Аналитик нажимает на зону или кандидата. 3. Система показывает карточку: сессии в сутки, загрузку, статус и пояснение. 4. Аналитик нажимает «Открыть паспорт». 5. Система сразу показывает паспорт из готового расчёта зон. 6. Система пересчитывает точку (UC-02) и дополняет паспорт резюме, блоком «При каком спросе точка окупится», таблицей по годам, профилем по часам, соседями, вариантами оборудования, окупаемостью и устойчивостью вывода |
| Альтернативы | 2а. «Проверить новую точку» и нажатие в любое место внутри МКАД. Паспорт открывается без готового расчёта, цифры появляются после шага 6. 2б. Нажатие за МКАДом. Карточка пишет, что модель считает только внутри пунктирного кольца. 2в. Нажатие по кружку с числом станций. Карта приближается к этим станциям. 4а. «Сравнить». Точка добавляется в таблицу «Ваши точки» (UC-04). 6а. Аналитик меняет сценарий в паспорте. Паспорт сразу показывает готовый расчёт зон и запускает пересчёт. 6б. Аналитик открыл другую точку до конца расчёта. Старый расчёт отменяется |
| Постусловие | Паспорт открыт, соседи с потерей клиентов отмечены на карте |
| Связанные истории | US-01, US-02, US-05, US-06, US-13, US-17 |

## UC-02. Подобрать конфигурацию и посчитать экономику

| | |
|---|---|
| Основной актор | Система, по вызову из UC-01 |
| Цель | Выбрать мощность и число постов под спрос точки и оценить окупаемость |
| Предусловия | Точка выбрана, известен ближайший центр питания |
| Основной поток | 1. Система ищет известную ТП 0,4 кВ ближе 200 м. 2. Система считает свободную мощность ближайшего центра питания. 3. Для каждой из шести конфигураций каталога (DC60-1, DC60-2, DC120-2, DC150-2, DC150-2S, DC300-4) система определяет класс подключения (BR-06). 4. Для каждой конфигурации система считает 12 локальных равновесий: 2026, 2028 и 2030 годы, лето и зима, будни и выходные, в выбранном сценарии. 5. Система рекомендует конфигурацию с наибольшим числом новых клиентов на 1 млн ₽ (BR-16). 6. Для стандарта DC150-2 система считает CAPEX, помесячный поток, окупаемость, NPV и устойчивость вывода (BR-10 - BR-14) |
| Альтернативы | 1а. Известной ТП ближе 200 м нет. Класс «А или Б», цена и срок по классу Б. 3а. Свободной мощности меньше, чем нужно конфигурации. Добавляется вариант с балансировкой мощности (*-bal), без цены. 3б. Класс В. Цена подключения не считается, конфигурация не рекомендуется. 6а. Включена компенсация МФППиП. Окупаемость и NPV считаются с тремя платежами компенсации (BR-09) |
| Постусловие | В паспорте таблица вариантов, окупаемость, NPV, устойчивость вывода и вердикт |
| Связанные истории | US-03, US-04, US-06, US-13, US-14 |

## UC-03. Изучить спрос во времени

| | |
|---|---|
| Основной актор | Аналитик развития сети |
| Цель | Увидеть, где и когда нужна зарядка |
| Основной поток | 1. Аналитик включает слой «Спрос по часам». Зоны решения скрываются, появляются настройки дня, сезона и часа. 2. Аналитик двигает ползунок часа 0-23. Система перекрашивает карту спроса без пересчёта сети. 3. Аналитик меняет будни и выходные, лето и зиму, год или сценарий. 4. Система пересчитывает сеть, открывает плановые станции города этого года и показывает карточку «Что изменилось в сети» |
| Альтернативы | 4а. Паспорт открыт. Система пересчитывает его под новые условия. 4б. В таблице «Ваши точки» есть точки. Система пересчитывает их баллы |
| Связанные истории | US-07, US-06 |

## UC-04. Сравнить несколько точек

| | |
|---|---|
| Основной актор | Аналитик развития сети |
| Цель | Быстро сравнить несколько адресов в одной таблице |
| Основной поток | 1. Аналитик открывает карточку или паспорт точки (UC-01). 2. Нажимает «Сравнить». 3. Система добавляет строку с баллом за подключение (по расстоянию до ТП и резерву), баллом за спрос в радиусе 2 км, баллом за конкуренцию (минус 8 баллов за каждую станцию в радиусе 1,5 км), итоговым баллом как средним из трёх и округом. 4. Аналитик повторяет для других точек и сортирует таблицу по любому столбцу. 5. Нажатие на строку открывает паспорт |
| Альтернативы | 2а. Точка уже в таблице. Повторно не добавляется. 4а. Аналитик удаляет строку, баллы спроса пересчитываются |
| Ограничения | Балл за спрос нормирован на максимум внутри текущей таблицы, поэтому баллы сравнимы только между строками одной таблицы. Таблица сделана по просьбе РСЗС как простой скоринг и не заменяет паспорт |
| Связанные истории | US-08 |

## UC-05. Посмотреть рекомендуемый портфель и карту зон

| | |
|---|---|
| Основной актор | Руководитель направления |
| Цель | Спланировать волну строительства и сравнить выбор модели с традиционным подходом |
| Предусловия | Портфель и карта зон заранее посчитаны скриптами compute-portfolio (15-25 минут) и compute-zones (около 50 минут) |
| Основной поток | 1. Руководитель открывает «Карту зон». 2. Система показывает зоны по статусу, число зон каждого статуса, вывод сценария и 10 кандидатов модели со статусом очереди. 3. Руководитель фильтрует кандидатов по статусу и меняет год или сценарий. 4. На вкладке «Сравнение» система показывает метрики модели и традиционного правила за 2026, 2028 и 2030 годы с отметкой лучшего. 5. Руководитель открывает паспорт любого места |
| Правила выбора | Традиционное правило ставит площадки по числу объектов в радиусе 500 м и плотности дорог за вычетом загрузки станций в радиусе 1 км. Модель выбирает жадно, по числу новых для сети клиентов на 1 млн ₽. В обеих стратегиях новые места не ближе 1 км друг к другу и везде ставится DC150-2. Портфель посчитан в базовом сценарии 30% |
| Ограничения | Обе стратегии оценены одной моделью. Это сравнение логики выбора, а не точности прогноза |
| Связанные истории | US-09, US-17 |

## UC-06. Проверить модель

| | |
|---|---|
| Основной актор | Внешний наблюдатель или разработчик |
| Цель | Убедиться, что расчёт корректен |
| Основной поток | 1. Пользователь открывает «Методику» и нажимает «Запустить тесты». 2. Система запускает в браузере тесты Т1-Т8 и Т10 на сети 2026 года. 3. Система показывает по каждому тесту результат и пояснение, Т11 помечен как ожидающий данных |
| Альтернативы | 2а. Разработчик запускает полные версии командой npm test. В браузере Т8 идёт на 3 кандидатах, а Т10 на трёх конфигурациях каталога |
| Связанные истории | US-10 |

## UC-07. Найти место по адресу

| | |
|---|---|
| Основной актор | Аналитик развития сети |
| Цель | Быстро перейти к станции, площадке или району |
| Основной поток | 1. Аналитик вводит в поиск улицу, район, оператора или номер площадки. 2. Система показывает до 10 совпадений: площадки пула и действующие станции, быстрые и медленные. 3. Аналитик выбирает строку стрелками и Enter или мышью. 4. Карта приближается к месту. Для площадки открывается карточка, станция обводится кольцом с подписью |
| Альтернативы | 2а. Ничего не найдено. Список пишет «Ничего не нашлось». 4а. Выбрана медленная станция. Слой медленных зарядок включается сам |
| Связанные истории | US-18 |
